# Лабораторная работа 11. Работа с деревьями

Реализовано **двоичное дерево поиска** (Binary Search Tree) и программа с меню для работы с ним.

## Что такое дерево

Дерево состоит из **узлов**. У каждого узла есть значение и ссылки на потомков. Верхний узел — **корень**, узлы без потомков — **листья**.

В **двоичном** дереве у узла не больше двух потомков: левый и правый.
В двоичном дереве **поиска** действует правило: в левом поддереве все значения меньше значения узла, в правом — больше.

```
        50
      /    \
    30      70
   /  \    /  \
  20  40  60  80
```

## Файлы

- `binary-search-tree.js` — классы `Node` (узел) и `BinarySearchTree` (дерево).
- `main.js` — программа с меню.

Запуск:

```bash
node main.js
```

Сначала вводятся начальные значения (Enter — пример 50 30 70 20 40 60 80), потом можно выбирать действия в меню. Программа рисует дерево «лёжа на боку»: корень слева, правое поддерево сверху, левое снизу.

## Операции

| Операция | Метод | Как работает |
|---|---|---|
| Создание дерева | `new BinarySearchTree()` | пустое дерево, `root = null` |
| Добавление | `insert(value)` | спускаемся от корня: меньше — влево, больше — вправо, пока не найдём пустое место; там создаём узел. Повторы не добавляем |
| Поиск | `search(value)`, `path(value)` | так же спускаемся по одной ветке; `path` возвращает путь от корня, например 50 → 30 → 40 |
| Удаление | `remove(value)` | три случая: лист — просто убираем; один потомок — ставим его на место узла; два потомка — заменяем значение наименьшим из правого поддерева и удаляем тот узел |
| Родитель | `parent(value)` | предпоследний узел на пути от корня |
| Потомки | `children(value)` | левый и правый потомки узла |
| Глубина узла | `depth(value)` | число рёбер от корня (у корня 0) |
| Высота дерева | `height()` | число уровней: 1 + большая из высот левого и правого поддеревьев |
| Минимум / максимум | `min()`, `max()` | самый левый / самый правый узел |
| Перебор узлов | `inOrder()`, `preOrder()`, `postOrder()`, `levelOrder()` | четыре вида обхода, см. ниже |

## Обходы дерева (перебор всех узлов)

Для дерева выше:

| Обход | Порядок | Результат |
|---|---|---|
| Симметричный (in-order) | левое → узел → правое | 20 30 40 50 60 70 80 — всегда по возрастанию |
| Прямой (pre-order) | узел → левое → правое | 50 30 20 40 70 60 80 |
| Обратный (post-order) | левое → правое → узел | 20 40 30 60 80 70 50 |
| В ширину (level-order) | по уровням, через очередь | 50 30 70 20 40 60 80 |

Первые три обхода рекурсивные. Обход в ширину использует очередь: берём узел из начала, кладём его потомков в конец.

## Сложность

- Поиск, добавление и удаление — O(h), где h — высота дерева.
- Если дерево сбалансировано (как в примере), h ≈ log₂ n — это быстро, как бинарный поиск.
- Если вставлять уже отсортированные числа (1, 2, 3, 4…), дерево вырождается в «палку», h = n, и операции становятся O(n).

## Возможные вопросы

- **Почему симметричный обход даёт отсортированный список?** Сначала выводится всё, что меньше узла (левое поддерево), потом сам узел, потом всё, что больше.
- **Почему при удалении узла с двумя потомками берём минимум правого поддерева?** Это следующее по величине значение: оно больше всех значений слева и меньше остальных справа, поэтому правило дерева не нарушается.
- **Что такое `#insertNode`?** Решётка делает метод приватным: он вспомогательный и вызывается только внутри класса.
