# Лабораторная работа 8. Сортировка вставками

## Словесное описание

1. Массив условно делится на две части: отсортированную слева и неотсортированную справа. Вначале отсортированная часть — это один первый элемент.
2. Берём первый элемент неотсортированной части — «ключ».
3. Идём по отсортированной части справа налево и сдвигаем на одну позицию вправо все элементы, которые больше ключа.
4. Вставляем ключ в освободившуюся ячейку. Отсортированная часть выросла на один элемент.
5. Повторяем, пока неотсортированная часть не закончится.

Так обычно раскладывают карты в руке: берут новую карту и вставляют её на своё место среди уже упорядоченных.

## Визуальный пример

Массив `5 2 4 6 1 3` (в скобках — отсортированная часть):

```
[5] 2 4 6 1 3
[2 5] 4 6 1 3        вставили 2: сдвинули 5 вправо
[2 4 5] 6 1 3        вставили 4: сдвинули 5
[2 4 5 6] 1 3        6 уже на месте, сдвигов нет
[1 2 4 5 6] 3        вставили 1: сдвинули все четыре элемента
[1 2 3 4 5 6]        вставили 3: сдвинули 4, 5, 6
```

## Запуск

```bash
node insertion-sort.js
```

Программа просит ввести числа через пробел (или нажать Enter для случайного массива) и печатает каждый шаг: какой элемент вставлен и как выглядит отсортированная часть.

## Как устроен код

- Внешний цикл `for (let i = 1; ...)` — берём ключ `key = array[i]`.
- Внутренний цикл `while (j >= 0)` идёт влево по отсортированной части и сдвигает элементы, большие ключа: `array[j + 1] = array[j]`.
- Когда встретили элемент не больше ключа (или дошли до начала), ставим ключ: `array[j + 1] = key`.

## Сложность

- **Худший и средний случай:** O(n²) — например, массив в обратном порядке: каждый ключ сдвигает всю отсортированную часть.
- **Лучший случай:** O(n) — массив уже отсортирован: для каждого ключа одно сравнение и ни одного сдвига.
- **Память:** O(1) дополнительно.
- **Устойчивость:** да — равные элементы не обгоняют друг друга, потому что сдвигаем только при строгом `>`.
- Хорошо работает на почти отсортированных и небольших массивах.
