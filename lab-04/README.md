# Лабораторная работа 4. Рекурсивные алгоритмы

Рекурсия — это когда функция вызывает сама себя для более простой версии той же задачи.

У каждой рекурсивной функции две части:

1. **Базовый случай** — самая простая ситуация, ответ на которую известен сразу (0! = 1, пустая строка — палиндром). На нём рекурсия останавливается.
2. **Рекурсивный шаг** — функция сводит задачу к такой же, но меньшей (n! = n · (n − 1)!) и вызывает сама себя.

Без базового случая функция вызывала бы себя бесконечно, и программа упала бы с ошибкой переполнения стека (`Maximum call stack size exceeded`).

Запуск: `node task01.js` и так далее. Ввод — модуль `input.js` (`askNumber`, `askInteger`, `askNumberList` — список чисел через пробел, `ask` — строка).

## Задачи

| № | Задача | Базовый случай | Рекурсивный шаг | Пример |
|---|---|---|---|---|
| 1 | Факториал n! | `n === 0` → 1 | `n * factorial(n - 1)` | 5! = 120 |
| 2 | n-е число Фибоначчи | F(0) = 0, F(1) = 1 | `fibonacci(n - 1) + fibonacci(n - 2)` | F(10) = 55 |
| 3 | xⁿ | `n === 0` → 1 | `x * power(x, n - 1)`; для n < 0 — `1 / power(x, -n)` | 2¹⁰ = 1024, 2⁻² = 0.25 |
| 4 | Строка — палиндром? | длина 0 или 1 → да | первый ≠ последний → нет, иначе проверяем строку без них: `text.slice(1, -1)` | «А роза упала на лапу Азора» → да |
| 5 | Бинарный поиск в отсортированном массиве | `left > right` → не найден | сравниваем со средним и ищем в левой или правой половине | [1 3 5 7 9 11], 7 → позиция 4 |
| 6 | Слова в обратном порядке | 0 или 1 слово — как есть | `[...reverseWords(rest), first]` | «мама мыла раму» → «раму мыла мама» |
| 7 | Разложение числа на сумму простых | n = 0 → пустая сумма | берём наибольшее простое p ≤ n и раскладываем n − p; если не вышло — пробуем меньшее p | 10 = 7 + 3, 27 = 23 + 2 + 2 |
| 8 | Количество цифр | n < 10 → 1 цифра | `1 + countDigits(Math.floor(n / 10))` | 12345 → 5 |
| 9 | Ханойская башня | 0 дисков — ничего не делаем | перенести n − 1 на вспомогательный, большой диск на целевой, n − 1 сверху на него | 3 диска → 7 ходов |

## Пояснения к сложным задачам

**Задача 2.** Простая рекурсия для Фибоначчи пересчитывает одни и те же числа много раз: чтобы найти F(5), она дважды считает F(3), трижды F(2) и т. д. Время растёт примерно как 2ⁿ, поэтому n ограничено 30.

**Задача 4.** Перед проверкой из строки убираются пробелы и знаки препинания, буквы переводятся в нижний регистр, «ё» заменяется на «е». Иначе фраза «А роза упала на лапу Азора» не считалась бы палиндромом.

**Задача 7.** Это перебор с возвратом. Например, для 27: берём 23, остаётся 4; 4 не простое, поэтому раскладываем 4 дальше — 3 + 1 не подходит (1 не раскладывается), значит, 2 + 2. Итог: 27 = 23 + 2 + 2. Функция возвращает `null`, если остаток разложить нельзя, и тогда пробуется меньшее простое число.

**Задача 9.** Минимальное число ходов для n дисков — 2ⁿ − 1. Оно растёт очень быстро, поэтому дисков не больше 10 (1023 хода).

## Возможные вопросы

- **Что такое стек вызовов?** Каждый вызов функции запоминается в стеке, пока не вернёт результат. При рекурсии вызовы накапливаются до базового случая, потом «сворачиваются» в обратном порядке.
- **Рекурсия или цикл?** Любую рекурсию можно переписать циклом. Рекурсия короче и нагляднее для задач, которые естественно делятся на подзадачи (Ханойская башня, бинарный поиск), но тратит больше памяти на стек.
- **Почему бинарный поиск быстрый?** Каждый шаг отбрасывает половину массива, поэтому для 1000 элементов нужно не больше 10 сравнений (log₂ n).
